## 4. CLI Reference, Exit Codes, JSON Schema & Hardware Guardrails

### Command-Line Interface (`verify/run_e2e.sh`)
```bash
verify/run_e2e.sh --tier <1|2|3|4> [--tier ...]   # Run selected tier(s) (repeatable or comma-separated)
verify/run_e2e.sh --all                           # Run all 4 tiers sequentially (164 tests)
verify/run_e2e.sh --self-test [--verbose]         # Run 18 isolated mktemp -d mutation/control suites
verify/run_e2e.sh --list                          # Print all 164 E2E tests + 18 self-tests and counts
```

**Optional Flags:**
- `--project-dir <path>`: Target Lean project root (default: parent directory of `verify/`, i.e. `/home/antigravity/shannon-c7`). Non-existent or empty directories are accepted and yield crisp structured `FAIL` results (`MISSING_DIR` / `MISSING_FILE`), never unhandled tracebacks.
- `--json-out <path>`: Emit structured JSON report conforming to schema v1.0.
- `--verbose` / `-v`: Print per-test diagnostic lines for PASS as well as FAIL.
- `--filter <substr>`: Case-insensitive substring filter over `test_id`, `feature`, and `title` (exits `2` if 0 tests match).
- `--lean-timeout <sec>`: Subprocess timeout for `lake env lean` (default `180`s; build timeout `max(300, lean_timeout)`).
- `--no-build`: Never invoke `lake build`; audit pre-built `.olean`s read-only.
- `-h` / `--help`: Display CLI usage and exit `0`.

### Exit Codes
| Code | Meaning |
|------|---------|
| `0` | All selected tests PASSED (`failed == 0`, `total >= 1`), or `--list` / `--help` succeeded. |
| `1` | One or more selected tests FAILED (missing artifacts, missing tools, missing Mathlib cache, hygiene/axiom/math/report failures, timeouts, or caught internal exceptions). |
| `2` | Invalid CLI usage (unknown flag, missing value, tier outside `{1,2,3,4}`, empty `--tier`, no mode selected, conflicting mode flags such as `--all --tier` or `--self-test`/`--list` combined with other modes, or `--filter` matched 0 tests). |

### Hardware & Environment Guardrails (2 vCPUs, 7.8 GiB RAM)
1. **Mathlib `.olean` Cache Pre-Flight Guard:** Before ever invoking `lake build` or `lake env lean`, `SuiteContext.check_mathlib_cache()` performs a bounded O(1)-best-case check for precompiled `.olean`s under `.lake/packages/mathlib`. If absent, it fails fast with `MATHLIB_CACHE_MISSING` and refuses to trigger source compilation of Mathlib on 2 vCPUs. `verify/` NEVER runs network downloads or `lake exe cache get`.
2. **Bounded Concurrency & RAM Monitoring:** `lake build` is strictly bounded to `-j 2` (`lake build -j 2 ShannonC7.Main`). Peak child RSS is monitored via Python `resource.getrusage(resource.RUSAGE_CHILDREN)` and `time.monotonic()` (never calling `/usr/bin/time`, which is absent on the VM) against a `7800 MiB` ceiling.
3. **Single-Invocation Caching:** `SuiteContext` caches the single `lake env lean verify/e2e_audit.lean` run, `lake build` check, `scripts/verify_axioms.sh` execution, repo-wide static hygiene walk, and constant extraction per CLI invocation.
4. **Zero Bytecode Pollution & Dynamic `elan` Discovery:** `run_e2e.sh` prepends `${ELAN_HOME:-$HOME/.elan}/bin` to `PATH` when present, exports `PYTHONDONTWRITEBYTECODE=1`, and invokes `python3 -B`, guaranteeing zero `__pycache__` or `.pyc` files under `verify/`. `T4-W07` prefers `project_dir/.venv/bin/python -B` when a project `uv` venv is provisioned.
5. **Python 3.12 Big-Int Guard:** `cross_check.py`, `common.py`, and `runner.py` raise `sys.set_int_max_str_digits(100000)`, use exact arbitrary-precision integer floor division in `format_fraction_down` (capped at `digits ≤ 50000`), use zero-GCD exact-integer cross-multiplication and `cubic_p_num` evaluation in `check_frontier_rational_bounds`, and apply exception-hardened `bit_length`-guarded diagnostic stringification (`_safe_int_preview`, exact `max_int_digits`-bounded `_safe_ratio_preview`, exact-`str` `_safe_str_obj`) and JSON sanitization (`_sanitize_details` with exact `type(obj) is int` / `type(k) is str` fast paths, `_sanitize_int` `int.__int__` and `float.__float__` coercion for `int`/`float` subclasses, `str`-subclass normalization, and `_safe_str_obj`-guarded `Path` handling) for `>100,000`-digit integers (including nested big-int containers and pathological `__str__`/`__repr__`/`__eq__`/`__lt__`/`bit_length` objects, `os.PathLike`, and `str`/`int`/`float` subclasses) across `execute_test` (coercing `bool(passed)` and `_safe_str_obj` on `code`/`message` into exact base types), `run_subprocess_safe` (`_safe_str_obj`-hardened `FileNotFoundError`/`TimeoutExpired`/`Exception` formatting for `cmd`, `timeout`, and `exc`), report verifiers, bounds/power/profile/witness diagnostics, and tier messages (safe for $d \ge 500$ where powers exceed 7,500 decimal digits and arbitrary malformed/giant inputs).

## 7. Graceful Failure & Zero-Traceback Semantics

- **NEVER silently skip or fake-pass:** Every real tier test (`--tier 1..4`, `--all`) whose target file, Lean module, `.olean`, tool, or report is missing returns `status: "FAIL"` with a machine-readable reason code (`MISSING_FILE`, `MISSING_DIR`, `MISSING_TOOL`, `MATHLIB_CACHE_MISSING`, etc.) and causes `run_e2e.sh` to exit `1`.
- **Zero Python tracebacks:** Every test executes inside `execute_test`'s exception boundary (`INTERNAL_EXCEPTION`) and `runner.py`'s top-level boundary, guaranteeing deterministic structured output and valid JSON even on completely empty or corrupted project directories.
